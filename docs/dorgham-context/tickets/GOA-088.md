# Summary

The scoring and matching pipeline runs on structured data, but the ingestion pipeline currently produces only unstructured vector chunks.

- **GOA-012 (Profile Matcher)** reads `program_requirements` for hard gates.
- **GOA-024 (Scholarship Matcher)** queries `ScholarshipProgram` records for its diff engine.

Neither table is currently populated by the ingestion pipeline.

GOA-010, GOA-015, and GOA-041 only emit `list[Document]` for similarity search, and there is no `scholarship_programs` table.

This ticket introduces a structured extraction pipeline so adapters perform a **dual-write**:

1. Structured database rows.
2. Existing chunked documents.

---

# Context — Structured Data Gap

The opportunity matching system depends on structured fields such as:

- Minimum ECTS
- Minimum IELTS
- GPA
- Deadlines
- Award amounts

However:

- GOA-015 adapters implement:

```python
SourceAdapter.scrape() -> list[Document]
```

which produces only unstructured chunks.

- GOA-012 reads:
  - `program.min_ects`
  - `program.accepted_degrees`

from `program_requirements`, but that table is never populated.

- GOA-024 scores:

> ScholarshipProgram records updated in the last 24 hours

but:

- `rag_db` contains no scholarship table.
- `notifications_sent.program_id` incorrectly references `program_requirements`.

Scholarships require fields like:

- deadline
- award amount

which university programs do not contain.

# Acceptance Criteria

## 1. New Database Table

Create a new table in `rag_db`:

```sql
CREATE TABLE scholarship_programs (
    id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name                  VARCHAR(255) NOT NULL,
    provider              VARCHAR(255) NOT NULL,
    country               VARCHAR(100),
    degree_level          VARCHAR(100),
    award_amount          VARCHAR(255),
    deadline              DATE,
    eligibility           JSONB NOT NULL DEFAULT '{}',
    citizenship_eligible  BOOLEAN DEFAULT TRUE,
    min_gpa               DECIMAL(4,2),
    min_ielts             DECIMAL(3,1),
    source_url            VARCHAR(500) NOT NULL,
    content_hash          VARCHAR(64) NOT NULL,
    last_scraped_at       TIMESTAMP DEFAULT NOW(),
    updated_at            TIMESTAMP DEFAULT NOW(),
    UNIQUE (provider, name)
);
```

Migration:

```
008_add_scholarship_programs.sql
```

added to the RAG service migration set.

# Implementation Notes

Each adapter already downloads the HTML.

Reuse that HTML to add:

```python
scrape_structured()
```

alongside the existing:

```python
scrape()
```

Signature:

```python
scrape_structured()
    -> list[ProgramRequirement | ScholarshipProgram]
```

For semi-structured sources:

- use an LLM extraction pass
- Claude Haiku
- JSON mode

to extract fields not easily available through HTML parsing.

Idempotency is based on:

```
content_hash
```

The RAG endpoints use:

```sql
INSERT ...
ON CONFLICT ...
DO UPDATE
```
