# GOA-029 — User Profile Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the profile experience so users can edit academic data (including Stage-2 scoring fields and IELTS overall + sub-scores), upload a CV with processing status, and inspect top opportunity matches with a detail modal — all wired through existing Gateway APIs.

**Architecture:** IA-aligned composition. `/profile` is the hub: always-editable React Hook Form with blur auto-save, an embedded CV upload section (shared with `/cv-review`), and an embedded top-10 matches section (shared with `/opportunities`). Canonical routes `/opportunities` and `/cv-review` stay. IELTS sub-scores are first-class persisted fields on User → `UserUpdated` → RAG `local_user_profiles`; Stage-2 matching continues to score on overall `ieltsScore` only.

**Tech Stack:** Next.js App Router (client components), React Hook Form, existing UI primitives (`Field`, `Input`, `Select`, `Modal`/Radix Dialog, `BandScoreInput`), Gateway proxies, NestJS User service + TypeORM, FastAPI RAG + SQL migrations, Playwright E2E.

## Decisions (locked)

| # | Choice | Implication |
|---|---|---|
| 1B | IA-aligned page composition | Reuse/extract shared CV + match components; do **not** delete `/opportunities` or `/cv-review` |
| 2B | Persist IELTS sub-scores | User DB migration + DTO/entity + event payload + RAG snapshot columns; frontend loads/saves all four + overall |

## Global Constraints

- Browser calls **only** the Gateway (`NEXT_PUBLIC_API_URL`, default `http://localhost:8080`) with `credentials: "include"`. Never call User/Writing/RAG directly from the browser.
- Profile updates are **`PUT /api/profile`** (not PATCH). Gateway → `PUT {user}/users/:jwtId/profile`.
- GPA scale is an explicit toggle persisted as `gpaScale` (`"4.0"` | `"100"`), never inferred from the numeric value.
- `workExperienceYears` and `extracurricularsScore` must be editable and saved — Stage 2 weights them at 25% + 20%.
- IELTS bands are half-steps only (`lib/ielts.ts`). Overall is computed via `computeOverallBand` when all four sections are set; override is allowed (same pattern as onboarding `LanguageStep`).
- Score color bands on the profile matches section (ticket AC): **green >80**, **amber 60–80**, **red <60**. Blocked programs stay a distinct neutral/blocked tone.
- Forms use `Field` for ARIA (`aria-invalid`, `aria-describedby`, `role="alert"` on errors). Full keyboard operability required.
- CV processing states: `uploading` → `processing`/`extracting` → `ready` (Writing service status is `processing` | `ready` | `failed`; UI may label `processing` as “Extracting…”).
- GOA-017 already stores `work_exp`, `extracurriculars`, `gpa_scale` (migration `009`). This plan only **adds IELTS sub-score columns** there — do not re-add scoring fields that exist.
- Prefer shared components over copy-paste between `/profile`, `/opportunities`, and `/cv-review`.
- Do not invent an external “apply URL” — **Apply** navigates to `/checklist/{programId}` (product application path). Keep “Ask GOA” as secondary if already on the card.

```ts
export function ProfileForm({
  profile,
  onOptimisticUser,
  onSaveError,
}: {
  profile: UserProfileDetail | null;
  onOptimisticUser?: ( partial: Partial<UserProfileDetail> ) => void;
  onSaveError?: (message: string) => void;
}): JSX.Element
```

- Autosave behavior:
  1. `onBlur` of a field (and `onChange` commit for Select/Combobox/MultiCombobox) triggers save of **full current valid payload** via `PUT /api/profile`.
  2. Skip save if validation fails for that field (or any field in the dirty payload).
  3. Skip save if payload deeply equals last successful payload (avoid loops).
  4. Optimistic UI: call `onOptimisticUser` with parsed values before the request resolves; roll back via `retry()` from parent on failure.
  5. Status region: `Idle` | `Saving…` | `Saved` | error `Alert` — `aria-live="polite"`.
  6. No explicit Save button.

- IELTS UI:
  - Four `BandScoreInput`s: Listening / Reading / Writing / Speaking.
  - Overall: derived via `computeOverallBand` when all four set; show read-only computed value by default; allow override (reuse onboarding pattern: small “Edit overall” control).
  - Payload always sends `ieltsScore` plus any provided sub-scores.

  async function saveFromBlur() {
    const values = getValues();
    const errors = validateProfile(values);
    if (Object.keys(errors).length) return;
    const payload = payloadFromValues(values);
    const fingerprint = JSON.stringify(payload);
    if (fingerprint === lastSaved.current) return;

    setSaveState("saving");
    onOptimisticUser?.(parsedDetailFromValues(values));
    try {
      await authApi.updateProfile(payload);
      lastSaved.current = fingerprint;
      setSaveState("saved");
    } catch (err) {
      setSaveState("error");
      onSaveError?.(apiErrorMessage(err) ?? "Could not save your profile.");
    }
  }

  return (
    <form noValidate className="flex flex-col gap-5" onSubmit={(e) => e.preventDefault()}>
      <div aria-live="polite" className="sr-only">
        {saveState === "saving" ? "Saving profile" : null}
        {saveState === "saved" ? "Profile saved" : null}
      </div>
      {/* visible subtle Saved / Saving indicator */}
      {/* fields: each Input/Select gets onBlur={saveFromBlur}; MultiCombobox onChange commits then saveFromBlur */}
    </form>
  );
}

test("profile autosaves GPA on blur and persists after refresh", async ({ page }) => {
  let storedGpa = 3.2;
  const profile = () => ({
    id: "user-1",
    email: "amina.hassan@example.com",
    subscriptionTier: "free",
    isVerified: true,
    profile: {
      userId: "user-1",

      targetCountries: ["Germany"],

      ects: 180,
      workExperienceYears: 1,
      extracurricularsScore: 5,
    },
  });

  await page.route(`${GATEWAY}/api/profile`, async (route) => {
    if (route.request().method() === "PUT") {
      const body = route.request().postDataJSON();
      if (typeof body.gpa === "number") storedGpa = body.gpa;
      await route.fulfill(withCors({ ok: true }));
      return;
    }
    await route.fulfill(withCors(profile()));
  });
  await page.route(`${GATEWAY}/api/writing/cv/latest`, (route) =>
    route.fulfill(withCors({ detail: "No CV uploaded yet" }, 404)),

  await gpa.fill("3.9");
  await gpa.blur();
