# Terraform runbook — creating and destroying the GOA environments

How to stand up staging or production from an empty account, and how to take it
back down without leaving anything billing.

Supersedes the environment-creation half of `GOA-073-DEPLOYMENT.md`, which
hardcodes one developer's local paths and assumes ownership of `goa.app` that
the project does not have. That document is still the reference for the
CloudFront/WAF acceptance checks.

---

## Before you start

**Both environments are currently destroyed.** As of 2026-08-05 the account
holds only the Terraform state bucket, the DynamoDB lock table, IAM roles and
AWS's default VPC. Everything below creates resources that bill by the hour.

### You need the secret values in hand

This is the one thing the repository cannot give you. Terraform creates the
Secrets Manager entries, but their *contents* come from `service_secret_values`
at apply time, and `.gitignore` correctly keeps them out of git:

- `ANTHROPIC_API_KEY` (AgentRouter) — writing, ingestion, orchestration, rag
- `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_HOST`
- `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` — user service
- `SES_SENDER_ADDRESS` — notification

`JWT_SECRET`, `INTERNAL_API_KEY`, `ADMIN_API_KEY` and the RDS master password
are generated by Terraform (`random_password`) and need nothing from you.

Put them in an **uncommitted** file — `*.tfvars` is gitignored except the two
committed environment files:

```hcl
# environments/staging.secrets.tfvars   (never commit this)
service_secret_values = {
  writing = {
    ANTHROPIC_API_KEY   = "..."
    LANGFUSE_PUBLIC_KEY = "..."
    LANGFUSE_SECRET_KEY = "..."
    LANGFUSE_HOST       = "https://cloud.langfuse.com"
  }
  ingestion = { ANTHROPIC_API_KEY = "..." }
}
```

### Select the workspace before you init

`terraform init` reads the state of the *currently selected* workspace. With
none selected it looks for a `default` state that has never existed in this
bucket and fails with:

```
Error: Error refreshing state: state data in S3 does not have the expected content.
The checksum calculated for the state stored in S3 does not match the checksum
stored in DynamoDB.
```

That error is misleading — nothing is corrupt. Fix:

```bash
printf 'production' > .terraform/environment     # or 'staging'
terraform init -reconfigure -backend-config=environments/shared.backend.hcl
```

## Why this is a two-phase apply

Terraform creates the ECR repositories, but ECS cannot start a task until an
image exists in them. On a fresh account the repositories are empty, so a single
apply leaves every service failing to stabilise.

Always: **apply ECR → push images → full apply.**

## Staging

```bash
cd infra/terraform

terraform workspace new staging     # first time only; `select` afterwards
terraform init -reconfigure -backend-config=environments/shared.backend.hcl
terraform validate
```

### Phase 1 — repositories

```bash
terraform apply \
  -var-file=environments/staging.tfvars \
  -var-file=environments/staging.secrets.tfvars \
  -target=module.ecr

terraform output -json ecr_repository_urls
```

### Phase 2 — build and push the images

Eight services: `gateway user orchestration speaking writing rag exam ingestion`.
ECR is **immutable**, so a tag cannot be overwritten — use the commit SHA.

```bash
aws ecr get-login-password --region eu-west-1 \
  | docker login --username AWS --password-stdin 114403655381.dkr.ecr.eu-west-1.amazonaws.com

TAG=$(git rev-parse HEAD)
for s in gateway user orchestration speaking writing rag exam ingestion; do
  docker build -t 114403655381.dkr.ecr.eu-west-1.amazonaws.com/goa-staging-$s:$TAG services/$s
  docker push  114403655381.dkr.ecr.eu-west-1.amazonaws.com/goa-staging-$s:$TAG
done
```

### Phase 3 — full apply

`ecs_image_tag` is deliberately **not** set in `staging.tfvars` (ECR immutability
means CI supplies the SHA), so you must pass it:

```bash
terraform plan \
  -var-file=environments/staging.tfvars \
  -var-file=environments/staging.secrets.tfvars \
  -var="ecs_image_tag=$TAG" \
  -out=staging.tfplan

terraform apply staging.tfplan
```

Check the plan for `destroy` lines before applying — on a clean create there
should be none.

### Verify

```bash
aws ecs describe-services --cluster goa-staging \
  --services $(printf 'goa-staging-%s ' gateway user rag exam) \
  --query 'services[].[serviceName,runningCount,desiredCount]' --output table

python -m pytest tests/smoke -v      # GOA_GATEWAY_URL=<alb dns>
```

## Production

Identical shape with `terraform workspace select production` and
`environments/production.tfvars`.

> ### This will stall unless you own the domain
>
> `production.tfvars` sets `domain_name = "goa.app"` and
> `enable_public_dns = true`, which creates a Route 53 zone and a **public ACM
> certificate validated by DNS**. If the registrar does not delegate to the
> Route 53 name servers Terraform creates, validation never completes and the
> apply hangs before eventually failing.
>
> Either delegate a domain you control:
>
> ```bash
> terraform apply -var-file=environments/production.tfvars \
>   -target=module.production_dns_zone -target=module.ecr
> terraform output production_name_servers    # set these at the registrar
> dig +short NS <your-domain>                 # wait until they match
> ```
>
> or use staging's approach and reach the stack by its ALB DNS name:
>
> ```hcl
> enable_public_dns                  = false
> create_self_signed_alb_certificate = true
> enable_cloudfront                  = false
> ```

## Teardown

**Clear the ALB's deletion protection first.** Production sets it on (staging
sets it `false`). Without this, `terraform destroy` reports success at the top
level while leaving the load balancer, its Elastic IPs and the entire VPC behind
it standing — the internet gateway cannot detach while the ALB's public
addresses are still mapped, so the whole network teardown silently stops:

```bash
aws elbv2 modify-load-balancer-attributes \
  --load-balancer-arn "$(terraform output -raw alb_arn)" \
  --attributes Key=deletion_protection.enabled,Value=false
```

Then destroy through a reviewed plan rather than `-auto-approve`:

```bash
terraform plan -destroy -var-file=environments/production.tfvars -out=destroy.tfplan
terraform show destroy.tfplan | head -50
terraform apply destroy.tfplan
```

### Always verify against the live account

`terraform destroy` can exit 0 with resources left behind. Sweep every region —
this is what caught the ALB:

```bash
for r in $(aws ec2 describe-regions --query 'Regions[].RegionName' --output text); do
  out=""
  n=$(aws ec2 describe-instances --region $r --filters Name=instance-state-name,Values=running \
      --query 'length(Reservations[].Instances[])' --output text); [ "$n" != "0" ] && out="$out EC2=$n"
  n=$(aws ec2 describe-nat-gateways --region $r --filter Name=state,Values=available \
      --query 'length(NatGateways)' --output text);            [ "$n" != "0" ] && out="$out NAT=$n"
  n=$(aws rds describe-db-instances --region $r --query 'length(DBInstances)' --output text)
                                                               [ "$n" != "0" ] && out="$out RDS=$n"
  n=$(aws elbv2 describe-load-balancers --region $r --query 'length(LoadBalancers)' --output text)
                                                               [ "$n" != "0" ] && out="$out ALB=$n"
  n=$(aws elasticache describe-cache-clusters --region $r --query 'length(CacheClusters)' --output text)
                                                               [ "$n" != "0" ] && out="$out REDIS=$n"
  n=$(aws ec2 describe-addresses --region $r --query 'length(Addresses)' --output text)
                                                               [ "$n" != "0" ] && out="$out EIP=$n"
  [ -n "$out" ] && echo "$r:$out"
done
```

Also check the global services, which no region sweep covers: CloudFront
distributions, Route 53 hosted zones ($0.50/month each), and WAF web ACLs
($5/month each).

## What it costs while it is up

| | Staging | Production |
|---|---|---|
| NAT gateway | $0.045/hr | $0.09/hr (two) |
| RDS | `db.t3.micro` ~$0.017/hr | `db.t3.small`, multi-AZ |
| ElastiCache | `cache.t3.micro` ~$0.017/hr | `cache.t3.small` ~$0.034/hr |
| ALB | ~$0.023/hr | ~$0.023/hr + LCU |
| Public IPv4 | $0.005/hr each | $0.005/hr each |
| **Roughly** | **$0.15–0.25/hr** | **higher** |

Staging is about **$2 for a working session**. The figure that matters is the
idle one: an environment left up over a month costs **$145–160** whether or not
anyone uses it, which is the entire project quota.

Interface VPC endpoints (sqs, secretsmanager) bill per AZ per hour and are easy
to forget — they are not visible in the EC2 console's instance list.

## Do not leave resources outside Terraform

The staging environment was orphaned once already: on 2026-08-01 a teardown
deleted the shared state bucket, and the ECS cluster, nine services, Lambdas and
VPC survived with nothing describing them. `terraform destroy` could not touch
them and they had to be deleted by hand.

If you create something outside Terraform, either import it or delete it the
same day. A resource that no state file knows about will not be cleaned up by
anyone's teardown.
