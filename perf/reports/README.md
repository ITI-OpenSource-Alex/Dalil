# Load-test and measurement evidence

Generated by `../run-speaking-load.sh` and by the build-tagged measurement in
`services/gateway/handlers/e2e_measure_test.go`. Only the runs the SLOs are
actually derived from are kept — intermediate runs against deterministic
stand-ins were deleted, because an evidence directory whose files disagree with
each other is worse than a small one.

All figures below are against the **real** `faster-whisper`/Piper sidecar and
the **real** provider, driven through the Gateway's WebSocket proxy, using the
real speech fixture in `../fixtures/`.

| File | What it is |
|---|---|
| `*-real-whisper-measurement.json` | STT sweep across 15/30/45/68s clips, 3 runs each. Source of the 0.6 transcription ratio budget. |
| `*-real-provider-measurement.json` | 8 full sessions, both providers real. Source of the 45,000 and 90,000 budgets. 32/32 agents completed. |
| `20260804T015248Z-*` | k6 at **50** concurrent sessions — 42/50 errored. The capacity wall. |
| `20260804T020234Z-*` | k6 at **5** concurrent — first-criterion budget breached. |
| `20260804T020439Z-*` | k6 at **2** concurrent — all budgets pass, 0 errors. |

The `-prometheus-after.txt` files are missing for these runs: the runner used to
abort on a non-zero k6 exit before capturing the after-snapshot, so every
*failing* run — the interesting ones — threw its evidence away. Fixed in
`run-speaking-load.sh`; runs from now on keep both snapshots regardless of
verdict.

**Concurrency summary.** The per-session SLOs hold at 1–2 concurrent sessions
and break by 5. The limit is CPU Whisper, not the Go service: 50 sessions × 30s
of audio at a ~0.33 ratio is ~500 CPU-seconds of transcription, which twelve
cores cannot serve inside any per-session budget. See GOA-032 in
`GOA_Sprint_4_Tickets.md` for the follow-ups this implies.
